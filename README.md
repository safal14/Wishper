# Wishper Studio

A local Flask client workspace for preparing the user's source video and a structured handoff package. Uploaded video is source footage that appears inside a video generated later by another system. This application does not create generated scenes or the final composition.

For the full plain-language explanation of the workflow, code, techniques, saved files, and current limits, see [WORKSPACE_GUIDE.md](WORKSPACE_GUIDE.md).

## Workflow

1. Upload one or more source videos. Remove or reorder clips in the source sequence.
2. Choose a 16:9 or 9:16 generated canvas. Trim and adjust each source clip.
3. Set source placement per clip: full frame, circle overlay, split screen, or a smart-screen timeline. The placement mockup uses a labeled placeholder for generated content.
4. Click **Prepare video & transcript** once. The app processes and merges the source clips, then transcribes the merged audio automatically. Whisper may take several minutes; if it fails, the same button retries transcription without merging again. The merged file keeps the source video's shape and does not bake overlay placement into it. Layout-only changes do not require preparing or transcribing again.
5. Review and edit the timestamped transcript. Edits save locally and update the captions file. The active preparation and transcript are restored after a page refresh, provided the source clips have not changed.
6. Choose a ready whiteboard generation style from the shared preview gallery. The browser sends only `style_id`; the Flask server adds its own style code to the handoff package.
7. Choose an included instrumental loop (Soft ambient is preselected), no music, or your own track; set volume and start time. Add the creative prompt.
8. Review the complete package and create it through the local `/api/server-package` endpoint. The UI does **not** transmit it to the other device yet; that handshake still needs to be agreed and implemented.
9. When a finished MP4 is available from the other device, use **Import finished MP4** in the client. Each import is stored as `output/<job-id>/generated-<unique-id>.mp4`; the latest is played and downloadable, while earlier versions stay on disk. Importing is a temporary local return path, not the future authenticated server callback.

The handoff JSON is stored at `output/<job-id>/server-package.json`. It includes references to the prepared source video, transcript, captions, music asset, generated canvas ratio, per-clip overlay settings, a global overlay timeline, and the prompt. When a style is selected, the server also includes its verified Revideo files in the package and agent prompt; only the ID comes from the browser. Large media files remain on disk and are referenced by path.

The `prompt` field is agent-ready: it combines the user's creative brief with a time-coded composition plan for overlay, split-screen, and full-frame sections. `user_prompt` keeps the original brief unchanged, while `layout_instructions` contains just the generated composition plan. The structured `overlay` object remains authoritative for exact timing, crop, and placement; each clip's `source_file` points to the original/processed clip whose pixel coordinates the crop describes. Timeline times refer to the prepared sequence, while original-source times account for trimming. Existing packages are unchanged; review and send again to create a package with these fields.

The included music files in `static/music/` are original procedural instrumentals generated by `scripts/generate_music.py`, not third-party recordings. The handoff marks a selected built-in track with `source: "builtin"` and `loop: true` so the downstream server can cover videos longer than the 24-second preview loop.

## Setup

Install `ffmpeg` and `ffprobe`, then:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

Open `http://127.0.0.1:5000`. The Whisper model defaults to `medium`; set `WHISPER_MODEL`, `WHISPER_DEVICE`, and `WHISPER_COMPUTE_TYPE` in the environment if needed. `MAX_UPLOAD_MB` defaults to 2048.

The `/api/process` endpoint remains available for direct transcription of an uploaded video. `POST /api/merge` now transcribes automatically and returns `segments` and `captions_url` with the prepared source. If transcription fails, it returns `transcription_error` and preserves the merged video; `POST /api/jobs/<job-id>/transcribe` is the retry path. `GET /api/workflow` restores the current preparation, `PUT /api/jobs/<job-id>/transcript` saves corrected captions, and `POST /api/jobs/<job-id>/result` imports a finished MP4 after the package exists. Repeated imports keep older versions and show the latest one.

## LAN generator connection

The handoff review now performs a handshake with the FastAPI generator, uploads the prepared MP4 to `POST /api/jobs`, polls the job, and imports `GET /api/jobs/{job_id}/video` when generation completes. By default it uses `http://192.168.1.16:8001`:

```bash
HOST=0.0.0.0 python app.py
```

`GENERATOR_SERVER_URL` and `GENERATOR_USER_ID` can override the generator address and multipart `user_id` field. The handshake defaults to the server-compatible `safal` user, client name `Wishper Studio`, and protocol version `test4-v1`; use `GENERATOR_USER_ID=deep` if that is the intended server account.

Whiteboard style setup, rendering, APIs, and tests are documented in [STYLES.md](STYLES.md).
